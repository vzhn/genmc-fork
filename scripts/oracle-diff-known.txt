# Known disagreements of scripts/oracle-diff.sh, one test per line:
#   <model or stronger:weaker pair> <category>/<test> <issue or reason>
# A listed test is reported as KNOWN, not MISMATCH, on any args line or
# variant, and may time out or fail to run; a listed test that runs and agrees
# on all of them fails the check: fix the issue, then delete its line. Under
# -p, a line may also record that the two models are not ordered on that
# program, saying why.

# rc11:lkmm is not an inclusion on every program: LKMM orders address,
# data and control dependencies, RC11 does not. A relaxed load of a pointer
# followed by a load through it (an address dependency) cannot read a value
# older than the one the pointer was published with under LKMM, and can under
# RC11. Same counts at 1b9ce333, before #77 and #263.
rc11:lkmm data-structures/qu dependency
rc11:lkmm data-structures/qu-opt dependency
rc11:lkmm data-structures/stc-opt dependency

# Nor on release cumulativity (#270, LKMM's prop): if t0 writes x0, then t2
# writes x0 and release-stores x2, which an RMW po-before t0's write reads,
# LKMM orders that RMW after t0's write ((prop \ id) & int is in hb), closing
# an hb cycle through t0's acquire load; RC11 needs an acquire read of x2. -lkmm explores 1039 executions of imm-sched-dup-revisit,
# as many as herd7 does on its kernel version (seq_cst as acquire/release).
rc11:lkmm infr/imm-sched-dup-revisit prop

# -lkmm misses an execution: the exhaustive dedup ignores the order of a
# refilled hole
rc11:lkmm gobench/grpc3017 #264
# -lkmm does not finish (-rc11 -exhaustive: 4 executions)
rc11:lkmm saver/loop-peel2 #271
